# keycloak_native_flutter example

Signs in to the demo realm of [`keycloak-native-auth/demo`](../../../keycloak-native-auth/demo) with `NativeLoginView` on any of its four native clients, then shows the claims and offers refresh, step-up, passkey registration, push enrollment with the approvals list, the flow log and logout.

Start the stack (`docker compose up` in `keycloak-native-auth/demo`), then `flutter run` here. The Android emulator reaches the host as `10.0.2.2`, the iOS simulator as `localhost`; override the defaults with `--dart-define=ISSUER=https://…/realms/demo` and `--dart-define=CLIENT_ID=…`. The **Server** button in the app bar changes the server URL, realm and client ID at runtime; they are saved with `shared_preferences`, and **Reset to defaults** goes back to the defaults. Saving signs out: the stored credentials and the local push enrollments of the old server are cleared on the device, and the SDK instances are configured again. Plain HTTP is accepted only for `10.0.2.2`, `localhost` and `127.0.0.1` (the Android debug network security config and the iOS `NSAllowsLocalNetworking` exception cover those); use `https://` for any other host. A client on another server must list `demoapp://auth/callback` as a redirect URI. Users: alice (`alice-password`, then TOTP), bob (`bob-password`); see [the sample app guide](../../../docs/sample-app.md). Push enrolls without delivery (`none`); passkeys need an HTTPS RP ID associated with the app.

`flutter test integration_test -d <device>` runs the live suite against the stack: alice with TOTP (computed from the realm's seeded secret), in-app push enrollment and the approvals list, and bob with an email code read from mailpit.

The Android build includes the Android SDK from `../../../android` (a Gradle composite build) and the iOS build the Swift package at the repository root, so SDK changes are picked up directly.

The app is framed with Phase Two's mark and colors (`design/brand` at the repository root). The launch screens are hand-written native files rather than `flutter_native_splash`: the Android 12 `windowSplashScreen*` attributes in `values-v31/styles.xml` with `launch_background.xml` before API 31, and the template's `LaunchScreen.storyboard` with a `LaunchBackground` color set on iOS. That is four small resource files and no generator to keep in step. The theme is `ColorScheme.fromSeed` from the brand blue, light and dark.
