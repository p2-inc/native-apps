# Example app

A React Native app that signs in to the demo realm of `keycloak-native-auth/demo` with the module's default screens (clients `demo-native`, `demo-native-passkey` with the passkey prompt shown at once, `demo-native-otp`, and `demo-native-pin` for PIN codes), then shows the token, refreshes it, builds resource request headers, steps up, registers a passkey, enrolls the device for push and answers sign-in requests, and logs out.

Start the compose stack (`cd keycloak-native-auth/demo && docker compose up --wait`, after `mvn -f ../pom.xml -DskipTests -DskipITs package`), then from `react-native/keycloak-native-react-native`: `yarn example start` and `yarn example android` or `yarn example ios`. The issuer defaults to `http://10.0.2.2:8080/realms/demo` on the Android emulator and `http://localhost:8080/realms/demo` on the iOS simulator. **Server settings** on the home screen changes the server URL, realm and client ID at runtime; they are saved with AsyncStorage (`@react-native-async-storage/async-storage`), and **Reset to defaults** goes back to the values above. Saving signs out: the stored credentials and the local push enrollment of the old server's demo clients are cleared on the device, and a new SDK instance is configured. Plain HTTP is accepted only for `10.0.2.2`, `localhost` and `127.0.0.1` (the iOS app's ATS exception is `NSAllowsLocalNetworking`, and the Android debug build allows cleartext for local development); use `https://` for any other host. A client on another server must list `demoapp://auth/callback` as a redirect URI. Passkeys need a public hostname with AASA / `assetlinks.json` (see docs/sample-app.md); push needs a signed-in user with DPoP-bound tokens and works without FCM or APNs, since the approvals list reads the pending requests itself.

Inside this repository the native SDKs are built from source: `android/settings.gradle` includes `../../../../android` as a composite build (which pins the example to the SDK's Android Gradle plugin 9.5.0 and Kotlin 2.4.21, and to Gradle 9.6.1, the line that runs both AGP 9.5 and React Native's Gradle plugin), and the pod resolves `KeycloakNativeCore` and `KeycloakNativePush` from the Swift package at the repository root.

The app is framed with Phase Two's mark and colors (`design/brand` at the repository root): a launch screen on both platforms without a dependency (the template's `LaunchScreen.storyboard` on iOS; on Android a `LaunchTheme` with the Android 12 `windowSplashScreen*` attributes, a layer-list before API 31, and `MainActivity` switching to `AppTheme`). The module's default screens keep their own look.
